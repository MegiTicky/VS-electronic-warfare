Current scanner behavior
------------------------

`scan(radius)` returns ships plus entities.

`scanForShips(radius)` returns Valkyrien Skies ships only.

`scanForEntities(radius)` returns non-player entities only.

`scanForPlayers(radius)` returns players only.

All returned targets are line-of-sight filtered in the current 0.3.0 source.

Ship LOS behavior:

    - For each detected VS ship, the scanner raycasts from the radar's
      world-space origin to the target ship's world-space center.
    - The raycast uses Valkyrien Skies `clipIncludeShips(...)` by reflection
      when available.
    - The target ship id is passed as `skipShip`, so the target ship's own
      blocks do not hide itself.
    - Intervening vanilla blocks and intervening ships block LOS.
    - Only ships with clear LOS are included in the returned Lua table.

Entity/player LOS behavior:

    - Entity and player targets are raycast from radar origin to entity bounding
      box center.
    - They are returned only when the ray is unobstructed.
    - When VS `clipIncludeShips(...)` is unavailable, LOS falls back to vanilla
      block clipping.

Returned entity maps include fields like:

    is_entity
    is_player
    id
    uuid
    name
    type
    pos
    velocity
    distance
    line_of_sight

Returned ship maps include fields like:

    is_ship
    id
    slug, if available
    pos
    velocity, if available
    distance
    size, if available
    mass, if available
    line_of_sight

Valkyrien Skies integration design
----------------------------------

The radar intentionally uses reflection for Valkyrien Skies helper access rather
than compile-time VS API dependencies.

Reasons:

1. Earlier mod attempts had runtime compatibility problems.
2. Reflection allows soft failure if helper signatures differ.
3. If VS ship scanning fails, `scanForShips` returns an empty list instead of
   crashing the game.
4. If VS raycasting fails, LOS falls back to vanilla block clipping.

Reflected helpers currently used:

    org.valkyrienskies.mod.common.VSGameUtilsKt.getShipsIntersecting(Level, AABB)
    org.valkyrienskies.mod.common.VSGameUtilsKt.getWorldCoordinates(Level, BlockPos, Vector3d)
    org.valkyrienskies.mod.common.world.RaycastUtilsKt.clipIncludeShips(...)

The scanner imports `org.joml.Vector3d`, which is available through the
Forge/VS runtime classpath in the tested modpack.

Dependency notes
----------------

`build.gradle` currently compiles against the CC:Tweaked jar in the active
JPxAA_ instance:

    C:\Users\lauya\curseforge\minecraft\Instances\JPxAA_\mods\cc-tweaked-1.20.1-forge-1.113.1.jar

Recommended in-game test plan
-----------------------------

1. Place a radar next to a ComputerCraft computer.
2. Run:

       local r = peripheral.find("vs_ew_radar")
       print(textutils.serialize(r.getConfigInfo()))
       print(textutils.serialize(r.scanForShips(128)))

3. Confirm a visible ship in open air is returned.
4. Place a wall between the radar and the ship center; confirm the ship is no
   longer returned.
5. Place another ship between the radar and target ship; confirm the target ship
   is filtered out.
6. Remove the blocker; confirm the target appears again.
7. Check `scanForEntities` and `scanForPlayers` if entity/player LOS behavior is
   important for the current test world.
